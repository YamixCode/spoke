# Spoke: правила работы с репозиторием

## Git

- Никогда не добавлять `Co-Authored-By`, `Generated with Claude Code`, `Claude-Session` и любые упоминания Claude в коммитах и описании PR.
- Не пушить напрямую в `main`: ветка `feat/…`, `fix/…`, `chore/…`, затем pull request в `main`.
- Не делать force push и не переписывать опубликованную историю без явного разрешения.
- Коммит и push только по просьбе пользователя.
- Сообщения коммитов: `feat: …`, `fix: …`, `chore: …`, `docs: …`. Независимые правки отдельными коммитами.
- Перед коммитом `git diff` и `git diff --check`.

## Pull request

Заголовок придумывать по фактическому diff. Описание в виде коротких release notes:

```markdown
## Что изменилось

- Основные изменения человеческим языком, без перечисления файлов и классов.

## Было → стало

- Было: … → Стало: …
```

Без списка файлов, раздела «Проверка», упоминаний тестов, CI и AI.

## Код

- Поясняющие комментарии не писать: понятные имена и простая структура. Допустимы только технические директивы (`noqa`, `type: ignore`, `pragma`, shebang).
- Docstring в одну короткую строку.
- Тесты: `.venv/bin/python -m pytest -q`.

## Версии и релизы

Релизы делает workflow `release` по тегу `vX.Y.Z` (архив с кодом и контрольная сумма); порядок в README. `SHELL_API` повышать, только когда меняются зависимости или модель и нужен новый DMG. Версия лежит в `spoke/__init__.py` (`__version__`), семантическая: PATCH для исправлений, MINOR для новых возможностей, MAJOR только по явному указанию. Повышать версию отдельным коммитом `chore: bump version to X.Y.Z` перед релизом.
