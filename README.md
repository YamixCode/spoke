# Spoke

Локальная диктовка для macOS: зажали клавишу, сказали, отпустили, и текст появился там, где стоит курсор. Диктовка Apple преобразует звук в текст, а Spokenly Cleanup редактирует готовые фрагменты на Mac.

Нужен Mac на Apple Silicon с macOS 26 или новее.

## Установка

1. Скачайте `Spoke-X.Y.Z.dmg` из раздела Releases, перетащите Spoke в «Программы» и запустите.
2. При первом запуске выдайте Spoke разрешения в «Системные настройки → Конфиденциальность и безопасность»: «Универсальный доступ», «Мониторинг ввода»; микрофон macOS спросит при первой записи. После выдачи перезапускать приложение не нужно.
3. Приложение подписано без Apple Developer ID. Если macOS не даёт открыть: «Системные настройки → Конфиденциальность и безопасность → Всё равно открыть» либо `xattr -dr com.apple.quarantine /Applications/Spoke.app`.

## Как пользоваться

- Зажмите Ctrl и говорите. Текст вставится после отпускания клавиши. В «Основных» можно назначить другую клавишу или сочетание, которое macOS передаёт приложению.
- Два быстрых нажатия Ctrl включают постоянную запись. Следующее нажатие Ctrl завершает и вставляет, Esc отменяет. Те же действия есть на плашке (✕ и ✓).
- В меню Spoke можно вставить или скопировать последний текст, открыть историю и настройки (⌘,). В истории доступны последние 15 диктовок. По умолчанию они сохраняются локально и доступны после перезапуска.
- Spoke распознаёт и обрабатывает фразы по ходу диктовки. При первом запуске macOS может скачать языковую модель, а Spoke загружает Spokenly Cleanup 1 (около 770 МБ). Пока Cleanup готовится, вставляется текст диктовки Apple. Состояние модели видно в «Настройки → Система».
- Запуск при входе включён по умолчанию и меняется в «Основных». В настройках также можно изменить плашку и звук, открыть разрешения и найти журнал.

Настройки лежат в `~/.config/spoke/config.json`, журнал в `~/Library/Logs/Spoke.log`.

## Обновления

«Проверить обновления…» в меню (и в Настройки → Система) смотрит последний релиз на GitHub. Если версия новее, предлагает обновиться: скачивает архив с кодом, сверяет контрольную сумму, ставит его в `~/Library/Application Support/Spoke/code` и перезапускает приложение. Сам `.app` и подпись не меняются, поэтому выданные разрешения сохраняются. Если присланный код сломан, Spoke при запуске откатывается на встроенный. Сбросить обновления: удалить `~/Library/Application Support/Spoke/code`.

Если обновлению нужны новые библиотеки (повышен `SHELL_API`), приложение предложит скачать свежий DMG из релиза. Репозиторий публичный, токен не нужен; для приватного форка задайте переменную `SPOKE_GITHUB_TOKEN`.

## Разработка

```
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
./start.sh
.venv/bin/python -m spoke --selftest файл.wav
.venv/bin/python -m spoke --devices
.venv/bin/python -m pytest -q
```

## Окно настроек

Формы окна настроек и системный распознаватель собираются в библиотеку `libSpokeUI.dylib`. Для сборки нужен SDK macOS 26 (Command Line Tools или Xcode). Скрипты `start.sh` и `packaging/build.sh` вызывают `./scripts/build_native.sh` самостоятельно. Библиотека входит в архив обновления.

## Сборка приложения и DMG

Нужна `.venv` с зависимостями из `requirements-dev.txt`.

```
./packaging/build.sh
```

Результат: `dist/Spoke.app` и `dist/Spoke.dmg`. Модель Cleanup скачивается один раз при первом запуске. Последующая обработка текста работает локально.

## Выпуск релиза

1. Поднять `__version__` в `spoke/__init__.py` отдельным коммитом `chore: bump version to X.Y.Z` и смержить в `main`. Если обновлению нужна несовместимая версия оболочки, поднять и `SHELL_API`.
2. Поставить тег: `git tag vX.Y.Z && git push origin vX.Y.Z`. Workflow `release` проверит, что тег совпадает с версией, соберёт `spoke-code-X.Y.Z.zip` с контрольной суммой и создаст релиз.
3. Только если поднимался `SHELL_API` или это первый релиз: `./packaging/build.sh` и приложить `dist/Spoke.dmg` к релизу (в релизе поправить имя на `Spoke-X.Y.Z.dmg`).
4. Для обычного обновления кода DMG пересобирать не нужно: установленные приложения возьмут архив через кнопку обновления.
